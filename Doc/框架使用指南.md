# 框架使用指南

## 适用范围

本指南面向当前仓库 `D:\Work\Unity_Project\TEngine_Game`，重点说明项目里现有的 TEngine、流程系统、热更入口、UI 模块和配置生成链路的实际用法。

本指南不追求介绍框架全部能力，只回答当前项目开发最常见的几个问题：

1. 游戏从哪里启动
2. 热更逻辑从哪里进入
3. 模块怎么拿
4. UI 怎么打开
5. 配置表怎么生成和接入
6. 新功能应该挂到哪里，而不是乱塞

## 框架优先开发原则

实现任何新功能前，先检查 TEngine、当前项目业务模块和现有工具是否已经提供对应方案。能够使用已有框架能力完成时，优先复用，不重复建设同类基础设施。

开发前建议按以下顺序检索：

1. 当前项目已有业务代码和 `Doc`
2. `GameModule` 已暴露的模块入口
3. `Books`
4. `UnityProject/repowiki/zh/content`
5. `UnityProject/Assets/TEngine`

UI、资源、配置、事件、流程、计时器、对象池、音频、本地化和调试功能应优先使用框架现有方案。只有现有能力明确不适用时才新增实现，并保持与框架生命周期和模块边界一致，避免形成第二套平行体系。

### 代码风格原则

- 代码应简洁、高效、易读，优先采用最直接且符合当前架构的实现。
- 不为未确认的未来需求提前增加抽象层、接口、基类或复杂扩展机制。
- 简单逻辑不拆成大量零散类和文件，不引入无法降低当前复杂度的设计模式。
- 只有能够消除实际重复、降低复杂度、改善已确认的性能瓶颈或符合框架既有模式时，才增加抽象和模块拆分。
- 性能优化需要明确依据；没有测量结果时，优先保证正确性和可维护性。

## 1. 启动链路

### Unity 场景入口

入口脚本：

- [GameEntry.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/GameEntry.cs:1)

当前职责：

1. 初始化核心模块：
   - `IUpdateDriver`
   - `IResourceModule`
   - `IDebuggerModule`
   - `IFsmModule`
2. 调用 `Settings.ProcedureSetting.StartProcedure()`
3. 挂 `DontDestroyOnLoad`

结论：

- 如果你要查“项目为什么一进场景就开始跑”，先看 `GameEntry.Awake()`
- 如果你要改启动流程，不要直接改场景乱绑对象，先查流程配置和流程类

### 流程链路

流程配置：

- [ProcedureSetting.asset](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/TEngine/Settings/ProcedureSetting.asset:1)

当前入口流程：

- `entranceProcedureTypeName: Procedure.ProcedureLaunch`

当前可用流程类包括：

- `ProcedureLaunch`
- `ProcedureLoadAssembly`
- `ProcedureStartGame`
- 以及资源初始化、下载、预加载等流程

结论：

- 启动顺序的“真配置”在 `ProcedureSetting.asset`
- 单看某个 `Procedure*.cs` 不够，要结合这个配置看谁是入口

## 2. 热更与游戏逻辑入口

热更入口文件：

- [GameApp.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/GameApp.cs:1)

当前入口方法：

- `GameApp.Entrance(object[] objects)`

当前行为：

1. 初始化事件系统 `GameEventHelper.Init()`
2. 接收热更程序集列表
3. 注册销毁监听
4. 调用 `StartGameLogic()`

当前默认游戏逻辑启动内容：

1. `RoguelikeGame.Instance.StartNewRun()`
2. `GameModule.UI.ShowUIAsync<BattleHudUI>()`
3. `GameModule.UI.ShowUIAsync<BattleControlUI>()`
4. `GameModule.UI.ShowUIAsync<BattleChoiceUI>()`
5. `GameModule.UI.ShowUIAsync<BattleSettlementUI>()`

结论：

- 如果你要改“真正的游戏开始后跑什么”，先看 `GameApp.StartGameLogic()`
- 这里适合挂“进入主菜单”或“进入当前主玩法”
- 不要把大段业务逻辑直接写进 `Entrance()`，那里应只做初始化和分发

## 4. UI 怎么接

UI 管理模块：

- [UIModule.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/Module/UIModule/UIModule.cs:1)

当前关键约定：

1. 场景中必须能找到 `UIRoot`
2. `UIModule` 初始化时会抓取：
   - `Canvas`
   - `UI Camera`
3. UI 根节点会被 `DontDestroyOnLoad`
4. 打开窗口统一走：
   - `GameModule.UI.ShowUIAsync<T>()`

窗口示例：

- [BattleHudUI.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/UI/BattleHudUI/BattleHudUI.cs:1)
- [BattleControlUI.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/UI/BattleControlUI/BattleControlUI.cs:1)
- [BattleChoiceUI.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/UI/BattleChoiceUI/BattleChoiceUI.cs:1)
- [BattleSettlementUI.cs](D:/Work/Unity_Project/TEngine_Game/UnityProject/Assets/GameScripts/HotFix/GameLogic/UI/BattleSettlementUI/BattleSettlementUI.cs:1)

结论：

- 新界面优先做成 `UIWindow` 体系内的窗口
- 不要绕开 `UIModule` 自己在业务代码里直接实例化 UI
- 临时调试 UI 可以存在，但不要继续承担核心业务逻辑

4. 被动道具表

## 6. 新功能应该挂到哪里

### 适合放在 `Procedure`

- 启动期流程
- 热更加载
- 资源初始化
- 进入游戏前的串行流程控制

### 适合放在 `HotFix/GameLogic`

- 主玩法逻辑
- 肉鸽单局流程
- 战斗、成长、事件、结算

### 适合放在 `Module/UIModule`

- 通用 UI 框架能力
- 窗口管理
- 界面资源加载
- 错误日志 UI

### 适合放在 `Configs/GameConfig`

- 敌人参数
- 武器定义
- 被动道具
- 升级选项
- 刷怪与难度阶段

### 不适合的做法

1. 把玩法规则长期写死在某个 UI 脚本里
2. 把内容定义硬编码在 `GameApp`
3. 新增系统时不走模块边界，直接跨层调用一串对象
