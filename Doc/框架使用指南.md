# TEngine 空工程骨架使用指南

## 当前状态

本项目已清理为 Unity + TEngine 空工程骨架。旧肉鸽玩法、旧 UI Prefab、旧视觉资产、旧测试、截图和业务文档已移除。

当前目标是提供一个可以开始其他游戏的干净工程，而不是继续旧项目。

## 保留的核心目录

- `UnityProject/Assets/TEngine`：TEngine 框架代码与设置。
- `UnityProject/Assets/Launcher`：启动器与热更加载 UI。
- `UnityProject/Assets/GameScripts/GameEntry.cs`：Unity 场景入口。
- `UnityProject/Assets/GameScripts/Procedure`：启动、资源初始化、热更加载等流程。
- `UnityProject/Assets/GameScripts/HotFix/GameLogic/GameApp.cs`：热更业务入口。
- `UnityProject/Assets/GameScripts/HotFix/GameLogic/GameModule.cs`：业务层统一模块访问入口。
- `UnityProject/Assets/GameScripts/HotFix/GameLogic/Module/UIModule`：基础 UI 窗口系统。
- `UnityProject/Assets/GameScripts/HotFix/GameProto`：Luban 生成代码和配置读取基础。
- `UnityProject/Assets/Editor`：编辑器工具。
- `UnityProject/Assets/Scenes/main.unity`：默认主场景。
- `UnityProject/Packages`：Unity 包依赖。
- `UnityProject/ProjectSettings`：Unity 工程设置。
- `Configs/GameConfig`：Luban 配置源与生成脚本。
- `Books`：TEngine 框架说明。

## 启动链路

### 场景入口

入口脚本：

- `UnityProject/Assets/GameScripts/GameEntry.cs`

当前职责：

1. 初始化基础模块。
2. 启动 `ProcedureSetting` 中配置的流程。
3. 保持入口对象不随场景销毁。

### 流程入口

流程配置：

- `UnityProject/Assets/TEngine/Settings/ProcedureSetting.asset`

常用流程目录：

- `UnityProject/Assets/GameScripts/Procedure`

如果要改启动流程，先查 `ProcedureSetting.asset`，不要只改某个 `Procedure*.cs`。

## 热更业务入口

入口文件：

- `UnityProject/Assets/GameScripts/HotFix/GameLogic/GameApp.cs`

当前行为：

- 初始化事件系统。
- 接收热更程序集列表。
- 打印热更入口日志。
- 调用空的 `StartGameLogic()`。

`StartGameLogic()` 当前不启动任何旧游戏逻辑。新游戏的首个入口应从这里接入，例如进入主菜单、进入测试场景或启动第一版玩法服务。

## 模块访问

统一入口：

- `UnityProject/Assets/GameScripts/HotFix/GameLogic/GameModule.cs`

已保留模块访问：

- `GameModule.Debugger`
- `GameModule.Fsm`
- `GameModule.Procedure`
- `GameModule.Resource`
- `GameModule.Audio`
- `GameModule.UI`
- `GameModule.Scene`
- `GameModule.Timer`
- `GameModule.Localization`

业务层优先通过 `GameModule` 访问框架模块，不要在各处散落 `ModuleSystem.GetModule<T>()`。

## UI 系统

基础 UI 目录：

- `UnityProject/Assets/GameScripts/HotFix/GameLogic/Module/UIModule`

保留能力：

- `UIWindow`
- `UIBase`
- `UIWidget`
- `UIModule`
- UI 资源加载接口
- UI 绑定组件工具
- 错误日志 UI 相关基础代码

新 UI 建议：

1. 先定义视觉样板，不直接批量做 Prefab。
2. 通过 `UIModule` 和 `GameModule.UI` 打开窗口。
3. 不要把玩法规则写进 UI 脚本。
4. UI Prefab 需要截图验收后再扩展到下一屏。

## 配置表链路

配置目录：

- `Configs/GameConfig`

保留内容：

- `Datas/__tables__.xlsx`
- `Datas/__beans__.xlsx`
- `Datas/__enums__.xlsx`
- `Datas/item.xlsx`
- `Defines/builtin.xml`
- `CustomTemplate/`
- `luban.conf`
- `gen_code_bin_to_project.bat`
- `gen_code_bin_to_project_lazyload.bat`

当前已移除旧肉鸽配置表。新游戏应重新设计业务表，不要恢复旧 `roguelike_*` 表作为默认内容。

## 新功能放置建议

适合放在 `Procedure`：

- 启动期流程
- 热更加载
- 资源初始化
- 进入游戏前的串行流程控制

适合放在 `HotFix/GameLogic`：

- 新游戏主玩法逻辑
- 游戏状态服务
- 战斗、关卡、成长、结算等业务模块

适合放在 `Module/UIModule`：

- 通用 UI 框架能力
- 窗口管理
- UI 资源加载
- UI 绑定基础能力

适合放在 `Configs/GameConfig`：

- 新游戏配置表源文件
- 生成模板
- 配置生成脚本

## 不要恢复的旧内容

- 旧肉鸽玩法代码。
- 旧 Battle 系列 UI。
- 旧 UI Prefab。
- 旧 `Roguelike_StarUI_*` 资源。
- 旧演示截图和 Steam 展示图。
- 旧阶段路线和开发日志。
- Unity 编辑器布局噪声。

## 新项目第一步建议

1. 写 `Doc/产品合同.md`，明确新游戏方向和禁区。
2. 写 `Doc/阶段计划.md`，只规划第一批最小可验收阶段。
3. 在 `GameApp.StartGameLogic()` 接入一个最小入口。
4. 建立第一条 PlayMode 测试。
5. 通过 `dotnet build UnityProject\UnityProject.sln --no-restore` 和 Unity MCP 真实验收。
