# Phase 1 原型开发合同：纯逻辑战斗核心

> 阶段：Phase 1  
> 日期：2026-06-19  
> 工程：Unity + TEngine  
> 目标：把 GDD 的最小战斗闭环落成可测试 C# 逻辑

## 1. 阶段目标

实现《仙途·天命》的第一块可验证核心：单场卡牌战斗。

阶段完成后，工程应能用代码创建一场“剑宗初始牌组 vs 炼气期敌人”的战斗，并验证以下规则：

- 回合开始抽牌到手牌上限。
- 玩家灵力每回合刷新。
- 打牌消耗灵力。
- 攻击造成伤害。
- 防御获得护盾。
- 敌人意图可见。
- 结束回合后敌人按意图行动。
- 破防会放大后续伤害。
- 灼烧会在回合开始造成持续伤害。
- 战斗能判定胜利或失败。

## 2. 输入设计

本阶段参考以下设计文件：

- `GDD_东方玄幻卡牌Roguelite.md`
- `卡牌池设计_剑宗.md`
- `敌人设计_炼气筑基期.md`
- `纸面玩测试方案.md`
- `平衡性调优表.xlsx`

优先采用纸面玩测试方案的最小范围：剑宗初始牌组、炼气期普通敌人、第一场精英相关规则。

## 3. 实现边界

### 做

- 新增纯逻辑命名空间 `GameLogic.Cultivation`。
- 新增战斗模型、卡牌定义、状态定义、敌人意图和战斗引擎。
- 新增种子数据，覆盖剑宗基础牌和炼气期敌人。
- 新增自动化测试，覆盖关键规则。
- 在热更入口输出原型可用日志，证明逻辑层可被项目调用。

### 不做

- 不做 UI。
- 不做卡牌美术、Prefab、动画、音效。
- 不做完整 Run 地图。
- 不做坊市、闭关、秘境。
- 不做道基树和存档。
- 不导入 4 门派全量卡池。
- 不复制 `Slay the Spire 2` 的代码、资源、文本或二进制内容。

## 4. 架构约束

- 战斗核心必须是纯 C# 逻辑，不依赖 Unity 场景对象。
- 随机性必须通过种子或显式随机源注入，便于测试与模拟。
- 卡牌效果先用结构化枚举表达，避免写成不可分析的字符串。
- 日志与 UI 通过结果对象读取，不让核心逻辑直接操作界面。
- 后续迁移 Luban 时，种子数据应能被配置表替换。

## 5. 验收标准

阶段通过必须满足：

- `dotnet build UnityProject\UnityProject.sln --no-restore` 通过。
- `git diff --check` 通过。
- EditMode 测试通过。
- Unity MCP 可以读取 Editor 状态。
- Unity 控制台没有新增 Error。

## 6. 后续衔接

Phase 1 完成后，Phase 2 才开始 UI。Phase 2 的第一目标是把同一套 `BattleEngine` 绑定到最小测试界面，而不是重写规则。
