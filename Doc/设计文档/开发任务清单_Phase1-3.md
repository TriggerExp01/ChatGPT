## Phase 1: 单场战斗原型（目标：2周）

### 目标
在Unity里跑通一场战斗——玩家用手牌打一个敌人，能赢能输。

### 任务拆解

#### 1.1 数据层（先做，不依赖UI）
- [ ] 用Luban配置表定义卡牌数据结构
  ```
  CardData表字段:
    id, name, rarity, type, sect, cost, element,
    modifiers: [{stat, operation, value, duration, target}],
    upgrade_tree, description, is_consumable
  ```
- [ ] 创建12张剑宗初始卡牌的Luban配表
  - 剑气诀×4, 破甲符×2, 护体真气×3, 剑步×1, 轻身术×1, 回春丹×1
- [ ] 创建1个敌人Luban配表：石魔（HP40, 防御2, 意图循环: 攻击6→防御5护盾→攻击8）
- [ ] 创建玩家数据：HP100, 灵力3/回合, 手牌上限5
- [ ] 实现C# Modifier数据模型（见GDD 9.4节）

#### 1.2 战斗核心逻辑（纯C#，不依赖MonoBehaviour）
- [ ] ModifierSystem：修饰器解析（平坦→百分比→SET，见GDD 9.4节）
- [ ] CombatEngine：战斗核心状态机（见GDD 9.7节）
- [ ] 牌库系统：洗牌、抽牌、手牌、弃牌堆、消耗堆
- [ ] 灵力系统：每回合刷新至上限、打出卡牌消耗灵力
- [ ] 回合流程：抽牌→玩家行动→敌人行动→回合结束
- [ ] 伤害计算：伤害 - 防御 = 实际扣血（最低1）
- [ ] 护盾系统：获得护盾、护盾吸收伤害、回合开始清0
- [ ] 敌人意图系统：按固定循环执行、意图通过GameEvent通知UI

#### 1.3 战斗UI（使用TEngine UIModule）
- [ ] 创建CombatWindow（UIWindow），按UI规范布局（见UI_UX设计规范.md）

- [ ] 灵力条UIWidget：显示当前/上限
- [ ] HP条UIWidget：玩家+敌人
- [ ] 敌人意图图标UIWidget：显示下回合行为（攻击/防御/数值）
- [ ] 结束回合按钮
- [ ] 战斗日志UIWidget：最近3条行动记录
- [ ] 用TEngine GameEvent订阅战斗事件更新UI（见GDD 9.6节）

#### 1.4 战斗结束
- [ ] 胜利条件：敌人HP≤0
- [ ] 失败条件：玩家HP≤0
- [ ] 结果界面：显示胜利/失败 + 本场统计（回合数、造成伤害、受到伤害）

## 给程序员的建议

### 数据先行——用Luban配置表
所有卡牌、敌人、法宝都用Luban配置表定义，不要硬编码。TEngine已集成Luban，配表字段见GDD 9.5节。设计师改Excel/JSON配表即可调数值，不用改代码。

### 修饰器系统是核心
GDD 9.4节定义的Modifier数据结构和ModifierResolver是整个游戏的骨架。花时间把这个系统做对，后续所有卡牌效果都只是配表数据。

### 战斗逻辑与UI分离——用TEngine GameEvent
战斗核心逻辑（CombatEngine）做成纯C#类，不继承MonoBehaviour。UI层通过TEngine GameEvent订阅战斗事件（见GDD 9.6节），逻辑层不引用任何UI代码。这样方便单元测试、方便调平衡。

### TEngine流程模块管理Run流程
用TEngine ProcedureModule管理主菜单→门派选择→地图→战斗→坊市→闭关→Boss→Run结算的流程切换（见GDD 9.10节）。每个流程节点对应一个Procedure类。

### 先跑通再优化
Phase 1的目标是"能玩"，不是"好玩"。先用色块代替美术、用数字代替动画。手感对了再加皮。
