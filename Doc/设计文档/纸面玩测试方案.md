> **目的**：在写任何代码之前，用纸和骰子验证核心战斗循环是否"好玩"。
> **原则**：早失败、低成本失败。纸面测试发现的问题改一行字，代码阶段发现的问题改一周。
> **测试范围**：剑宗初始牌组 × 炼气期前3场战斗 × 第一场精英

## 一、测试准备

### 1.1 需要打印/制作

**卡牌**（打印在A4纸上裁剪）：
- 剑气诀 ×4
- 破甲符 ×2
- 护体真气 ×3
- 剑步 ×1
- 轻身术 ×1
- 回春丹 ×1

**敌人卡**（打印，每张一个敌人）：
- 石魔 ×1
- 火蝠 ×1
- 石魔统领（精英）×1

**记录表**（打印多份，见附录）

### 1.2 需要准备

- 六面骰子 ×2（用于随机数判定）
- 计数器/硬币（用于追踪HP、护盾、灼烧层数、剑气印记）
- 笔 + 测试记录表
- 计时器（记录每场战斗用时）

### 1.3 测试人员

至少 **2人**：
- **玩家**：操作卡牌，做出决策
- **观察者**：记录数据、计时、记录玩家的口头评论

理想情况是找 **3-4组** 不同背景的测试者：
- 有卡牌游戏经验者
- 无卡牌游戏经验者
- 设计师本人（必须，作为基准）

## 二、测试脚本

### 测试1：石魔战（基础教学战斗）

```
预设: 玩家HP=100, 灵力=3/回合, 手牌上限=5
敌人: 石魔 HP=40, 防御=2, 灵力=3

回合流程:
  玩家回合开始 → 抽至5张 → 使用灵力出牌 → 回合结束
  → 石魔按意图行动 → 回合结束效果 → 新回合

石魔意图(循环):
  回合1: 攻击6
  回合2: 防御 获得5护盾
  回合3: 攻击8
  重复...
```

**测试目标**：
- [ ] 玩家能否在3-4回合内理解基本操作？
- [ ] 玩家能否发现"破甲符→剑气诀"的协同？
- [ ] 战斗是否在4-6回合内结束？
- [ ] 玩家HP剩余多少？（目标：剩余 > 60%）

**观察要点**：
- 玩家第一次看到敌人"防御"时的反应
- 玩家是否主动尝试牌序优化
- 是否有任何"不知道该怎么办"的停顿

---

### 测试2：火蝠战（DOT机制教学）

```
预设: 继承测试1的HP状态（模拟连续战斗）
敌人: 火蝠 HP=32, 防御=0, 灵力=3

火蝠意图(循环):
  回合1: 攻击4 + 灼烧1层(2回合)
  回合2: 攻击4 + 灼烧1层(2回合)
  回合3: 强化 下回合攻击+4
  回合4: 攻击8(强化后)
  重复...
```

**测试目标**：
- [ ] 玩家是否理解灼烧的"延迟伤害"概念？
- [ ] 玩家是否调整策略应对DOT？（如更积极进攻缩短战斗）
- [ ] 战斗结束时玩家HP剩余 > 40%？
- [ ] 玩家是否使用了回春丹？

**观察要点**：
- 玩家是否计算"现在掉4血+下回合掉1血"的总伤害
- 玩家对灼烧的态度：恐慌 or 无视？

---

### 测试3：石魔统领战（精英考验）

```
预设: 继承测试2的HP状态 + 从测试1/2中各获得1次卡牌奖励
      (从剑宗灵品卡池随机3选1，允许跳过)

卡牌奖励模拟（掷骰子决定出现哪3张）:
  1-2: 七绝剑气 + 破军斩 + 剑意贯通
  3-4: 万剑诀 + 金钟罩 + 剑气护壁
  5-6: 幻影剑步 + 聚灵术 + 万剑诀

玩家选择1张加入牌组（或跳过），然后洗牌。

敌人: 石魔统领 HP=65, 防御=3, 灵力=3

石魔统领意图(循环):
  回合1: 攻击8
  回合2: 召唤 1只石魔(HP20/防御1/攻击4)
  回合3: 横扫 全体5伤害
  回合4: 防御 获得10护盾
  重复...
```

**测试目标**：
- [ ] 玩家能否应对"召唤物+本体"的多目标局面？
- [ ] 玩家如何处理AOE攻击（横扫）？
- [ ] 战斗是否在5-8回合内结束？
- [ ] 战斗结束时玩家HP剩余 > 25%？（精英战应有明显消耗）

**观察要点**：
- 玩家先打召唤物还是先打本体？（两种策略都合理，看偏好）
- 新获得的卡牌是否被实际使用？效果如何？
- 是否有"啊哈！"时刻？

---

### 可选测试4：战斗奖励"跳过"行为

```
场景: 测试2胜利后，展示3张奖励卡牌
故意展示3张与当前牌组不协同的牌
观察玩家是否选择"跳过"
```

**测试目标**：
- [ ] 玩家是否意识到"跳过"是选项？
- [ ] 如果不提示，多少玩家会主动跳过？
- [ ] 如果提示"可以跳过"，玩家的反应？

## 四、判定标准

### 4.1 什么算"通过"

| 测试 | 通过标准 |
|------|----------|
| 测试1(石魔) | 所有测试者3回合内理解操作；剩余HP > 60%；无"不知道该干什么"的停顿 |
| 测试2(火蝠) | 所有测试者正确理解灼烧机制；剩余HP > 40%；战斗节奏紧凑 |
| 测试3(精英) | 至少80%测试者胜利；剩余HP > 20%；精英战有明显压力感但非绝望 |
| 综合 | 所有测试者表示"想再打一场" |

### 4.2 什么算"需要调整"

| 现象 | 可能的问题 | 调整方向 |
|------|-----------|----------|
| 测试1超过6回合 | 初始牌组伤害太低 | 剑气诀伤害 8→9 |
| 测试1剩余HP < 50% | 防御牌不够或敌人太强 | 石魔伤害 6→5 |
| 测试2中灼烧被无视 | 灼烧伤害太低，无威胁感 | 灼烧 1/回合→2/回合 |
| 测试2剩余HP < 20% | 灼烧过强或防御不足 | 火蝠伤害 4→3 |
| 测试3全员失败 | 精英过强 | 石魔统领HP 65→55 |
| 测试3全员轻松通过 | 精英太弱 | 石魔统领伤害+2 |
| 无一人选择"跳过" | 跳过选项不够明显或卡牌都太好 | 增加提示或调整卡池 |
| 玩家频繁计算失误 | 数值太复杂 | 简化数值为5的倍数 |

### 4.3 什么算"失败"——立即停止测试

- 任何测试者表示"无聊"
- 战斗超过12回合仍未结束
- 玩家在战斗中"挂机"（不出牌等死）
- 连续3个测试者出现同样的困惑

## 五、迭代流程

```
第1轮测试 (3-4人)
  → 收集数据
  → 调整数值（仅调整数值，不改机制）

第2轮测试 (新3-4人)
  → 验证调整效果
  → 如果通过 → 进入第3轮（扩大范围）
  → 如果仍有问题 → 考虑机制调整

第3轮测试 (5-8人，包含非设计师)
  → 验证整体平衡
  → 收集主观体验反馈
  → 确定"好玩"基线
```
