# 节点1技术方案冻结落地

## 文档目的

对应排期文档中的“节点 1：2026-06-14 前，技术方案冻结”，将当前原型代码的边界、输入模型、配置表草案与 UI 信息架构固定下来，作为后续节点 2（配置化）与节点 3（实时战斗）的约束基线。

## 当前模块边界（已落地）

### Run（单局状态、房间推进、结算）

- `RoguelikeRunService`：创建单局、房间生成、房间推进、单局预览
- `RoguelikeRunState`：单局状态容器（玩家、金币、房间索引、遗物）
- `RoguelikeGame`：单局生命周期控制（开始、胜负阶段切换）

### Combat（战斗结算）

- `RoguelikeRunService.ResolveCurrentRoomStep`：单步战斗结算、伤害与死亡判定
- `RoguelikeRunService.ResolveCurrentRoom`：整房间自动结算循环

说明：当前仍为“数值回合模拟式”战斗实现，后续节点 3 替换为实时战斗控制器与敌人 AI。

### Progression（遗物、奖励、商店选择）

- `RoguelikeProgressionModule`：奖励选项生成、购买与选择应用
- `RoguelikeChoiceOption`：奖励项定义（标题、描述、价格、效果）

### Config（配置加载、索引、校验）

- `RoguelikeConfigModule`：聚合内容配置与奖励配置入口，并执行基础校验
- `RoguelikeContentCatalog`：敌人/遗物内容配置（当前为默认实现）
- `RoguelikeChoiceCatalog`：奖励/营火/宝箱/商店选项池配置（当前为默认实现）

说明：当前完成“配置入口与校验层”固定，下一节点改为 Luban 表驱动替换默认实现。

### UI（局内 HUD、奖励、商店、结算）

- `BattleMainUI`：当前原型 UI 容器
- `RoguelikeText`：房间名、阶段名、提示文案统一出口

说明：逻辑层已避免继续在 UI 中新增核心规则，后续拆分正式面板。

## 轻操作最小交互模型（冻结版）

1. 左侧摇杆/虚拟方向键：角色移动
2. 自动普攻：进入攻击范围自动触发，具备攻速参数
3. 主动技能键：单技能，含冷却与释放反馈
4. 闪避/位移键：短 CD、生存向位移

## 配置表清单与字段草案

以下为节点 2 必做表，字段以“最小可玩”优先：

1. 敌人表 `Enemy`
- `Id`、`Name`、`Type(Common/Elite/Boss)`、`Hp`、`Atk`、`Def`、`CritChance`、`CritMultiplier`、`DepthScale`

2. 遗物表 `Relic`
- `Id`、`Name`、`Desc`、`Rarity`、`EffectType`、`EffectValue1`、`EffectValue2`

3. 升级选项表 `UpgradeOption`
- `Id`、`Name`、`Desc`、`PoolType`、`Cost`、`EffectType`、`EffectValue1`、`Weight`

4. 商店商品表 `ShopItem`
- `Id`、`Name`、`Desc`、`Cost`、`EffectType`、`EffectValue1`、`Weight`、`UnlockDepth`

5. 房间奖励表 `RoomReward`
- `Id`、`RoomType`、`RewardType(Gold/Heal/Relic/OptionPool)`、`Amount`、`RelicPool`、`OptionPool`

6. 事件选项表 `EventOption`
- `Id`、`EventId`、`Title`、`Desc`、`Cost`、`EffectType`、`EffectValue1`、`NextEventId`

## 正式 UI 信息架构草图（节点 5 输入）

1. 局内 HUD
- 生命/护盾、技能区、金币、当前房间类型、迷你路线

2. 奖励选择面板
- 三选一卡片、效果预览、确认交互

3. 商店面板
- 商品列表、价格、持有金币、离开商店按钮

4. 事件面板（营火/宝箱/特殊事件）
- 事件描述、选项按钮、结果反馈

5. 暂停与结算面板
- 暂停设置、失败结算、胜利结算、再来一局

## 冻结约束

1. 不再把新规则直接写进 `BattleMainUI`
2. 新增成长或奖励规则必须进入 `Progression`/`Config` 边界
3. 新增内容数据优先写表，不新增同类硬编码池
