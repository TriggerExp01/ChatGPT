# 肉鸽系统设计总览

## 当前产品定位

- 类型：轻操作肉鸽
- 视角与节奏：实时战斗，小局循环，强调局内成长
- 当前开发策略：先做可玩的正式原型，再扩内容，不先做大而全

## 当前确认的交互模型

- 玩家移动
- 自动普攻
- 一个主动技能
- 一个闪避或位移技能

## 当前确认的系统模块

### 1. 单局流程模块

职责：

- 开局
- 房间推进
- 胜负结算
- 奖励选择
- 商店和事件流程

### 2. 战斗模块

职责：

- 玩家控制
- 敌人行为
- 技能释放
- 伤害结算
- 死亡与清场判定

### 3. 成长模块

职责：

- 局内升级
- 遗物效果
- 商店购买收益
- 数值成长和流派差异

### 4. 配置模块

职责：

- 敌人、遗物、事件、商品、奖励等内容的配置化
- 配置生成、加载、索引和校验

### 5. UI 模块

职责：

- 局内 HUD
- 奖励选择面板
- 商店面板
- 事件面板
- 结算与暂停面板

## 当前明确的工程原则

1. 用户可见文案优先使用中文。
2. 重要开发结论落到 `Doc`，不只保留在对话中。
3. 内容数据尽量配置化，避免长期硬编码。
4. 临时调试 UI 不再继续承担核心业务逻辑。
5. 先保证完整单局闭环，再追求内容量。

## 当前主要风险

1. 如果战斗、流程、UI 不尽快解耦，后续正式化成本会持续升高。
2. 如果配置化只做一半，会形成代码和配置双源维护问题。
3. 如果过早追求大量内容，会拖慢正式结构和可交付版本落地。
