# 肉鸽系统设计总览

## 当前产品方向

- 类型：类《吸血鬼幸存者》的俯视角 2D 自动战斗肉鸽。
- 核心体验：玩家移动、武器自动攻击、持续刷怪、经验升级、随机强化和构筑成长。
- 当前策略：按阶段完成并运行验收，不跨阶段堆功能。
- UI 与商业化展示方向：二次元轻幻想 Bullet Heaven UI，强调角色感、卡牌奖励、图标化构筑、低遮挡战斗 HUD 和 Steam PC 玩家可读性。
- 当前路线：[类吸血鬼幸存者阶段开发路线.md](D:/Work/Unity_Project/TEngine_Game/Doc/类吸血鬼幸存者阶段开发路线.md:1)

## 当前系统职责

- 单局流程：开始、游玩、升级暂停、死亡、结算、重开。
- 玩家：移动、生命、属性和受伤。
- 敌人：生成、追踪、攻击、受伤和死亡。
- 武器：自动搜敌、攻击、伤害、多武器成长和配置化基础数值。
- 成长：经验、等级、升级三选一、武器升级和被动道具。
- 关卡：时间、配置化刷怪节奏、难度成长、固定地图边界和后续地图扩展。
- UI：生命、经验、等级、时间、击杀、升级和结算。
- 性能：敌人、掉落物、投射物运行时对象接入 TEngine `MemoryPool`，战斗临时视图在舞台内复用。
- 配置：敌人基础数值、升级奖励、被动效果、武器基础数值和刷怪阶段已接入现有 Luban 配置表，运行时保留配置不可用回退。
- 拾取：经验与金币掉落已具备吸附和收集逻辑，阶段 14 已覆盖边界夹取与经验拾取验收。
- 反馈：受击闪白、拾取脉冲、相机震动和最小音效已接入轻量运行时表现，音频播放复用 TEngine 音频模块。
- 内容扩展：阶段 16-20 已完成第一轮内容扩展，包含配置表补齐、刷怪配置化、第三武器、被动解释层和最小音频反馈。

## UI 与美术资源策略

- 目标风格：二次元轻幻想，不走暗黑硬核，也不走廉价手游满屏按钮、红点和礼包入口。
- 战斗 HUD：左上角色头像、生命、经验和等级，中上生存时间与敌人压力，右上武器和被动图标槽，底部仅保留低遮挡操作提示。
- 升级选择：三张卡牌式奖励界面，包含图标、标题、效果描述、价格或条件、可选和不可选状态。
- 结算界面：显示胜利或失败标题、生存时间、击杀、金币收益、永久成长进度和重新开始入口，可预留角色立绘或剪影空间。
- 资产来源优先级：免费可商用资源 + GPT 绘画。免费资源用于字体、基础 UI、占位图标和简单特效；GPT 绘画用于角色头像、奖励卡牌、武器图标、被动图标、掉落物和 Steam 展示图。
- 授权要求：所有外部免费资源必须记录来源、作者、许可和用途。优先使用 CC0 或明确可商用资源；CC-BY 资源必须保留署名信息；禁止商用或许可不清的资源不进入项目。

### UI 质量提升固化规则

- 后续正式定 UI 风格前，必须先收集 1-3 张目标参考图，再拆解色板、字体层级、按钮形态、面板密度、HUD 遮挡率和卡牌样式，避免 Codex 仅凭工程可用性自由发挥。
- UI 实现优先沉淀可复用组件，例如 HUD 面板、图标槽、奖励卡、按钮、进度条和提示条；新增界面优先组合既有组件，不重复手搓一次性样式。
- 每个 UI 表现阶段必须进行截图级验收，重点检查文字裁切、信息遮挡、颜色脏污、按钮可识别性、卡牌层级和 Steam 展示图可用性；代码测试通过但截图观感不达标时不视为 UI 验收完成。
- 免费资源只能作为过渡或明确可商用资产使用；如果后续要显著提升观感，优先评估完整授权的商业 UI 包或统一生成的一组图标/卡牌/头像资产，并继续写入许可清单。
- UI 视觉表现阶段必须和玩法、数值、配置、结构阶段拆开推进；未进入 UI 风格定稿阶段时，功能与结构开发不被 UI 抛光任务阻塞。

## 工程原则

1. 优先复用 TEngine 和项目已有方案。
2. 代码简洁、高效，不为未确认需求过度设计。
3. 每次只推进一个阶段，通过 Unity 运行验收后再进入下一阶段。
4. 原型阶段优先保证核心闭环，Luban 配置化和内容扩展按阶段后置。
5. 用户可见文案和项目文档使用中文。

## 当前主要风险

1. 当前部分生存玩法逻辑仍集中在 `RoguelikeGame`；阶段 64 已先把刷怪阶段解析和敌人配置选择拆入 `RoguelikeSpawnDirector`，阶段 65 已把升级三选一奖励池构建拆入 `RoguelikeRewardDirector`，阶段 66 已把武器运行时解释拆入 `RoguelikeWeaponDirector`，后续仍需要按实际复杂度继续小步拆分拾取、反馈、展示构图和结算存档等边界。
2. 当前音效为最小 WAV 占位资源，后续正式资源替换时仍需沿用 TEngine `IAudioModule` 和 `Assets/AssetRaw/Audios` 地址链路。
3. 当前 UI 缺少最终目标参考图和统一视觉基准，后续定风格前需要按 UI 质量提升固化规则先做参考拆解与截图验收。
4. 当前视觉表现仍以运行时生成 Sprite 为主，正式 Prefab 和美术资源尚未系统接入。
5. 后续不要在已完成的配置化基础上引入第二套资源或配置框架。
