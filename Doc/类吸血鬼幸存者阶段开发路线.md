# 类吸血鬼幸存者阶段开发路线

## 项目目标

使用 Unity 和当前 TEngine 项目实现一个类《吸血鬼幸存者》的 2D 自动战斗肉鸽游戏。

核心体验：

- 玩家控制角色移动。
- 武器自动寻找并攻击敌人。
- 敌人从四周持续生成并追击玩家。
- 击杀敌人获得经验，升级时随机三选一。
- 随着时间推进形成武器、被动和数值构筑。

## 执行规则

1. 每次只推进一个阶段。
2. 当前阶段完成 Unity 运行验收后，再进入下一阶段。
3. 优先复用 TEngine 与当前项目已有模块。
4. 代码保持简洁，不为后续阶段提前建设复杂系统。
5. 对象池、Luban 配置化和内容扩展在核心闭环稳定后再推进。

## 当前推进边界

阶段 15 已完成规划，当前路线文档内阶段已全部推进完毕。下一步不直接堆新系统，应先按阶段 15 计划拆出新的实施阶段：

1. 第一批内容扩展优先补内容表和运行时最小解释逻辑，不改启动、热更或 UI 基础框架。
2. 每次只落地一个内容方向，例如敌人、武器、被动、刷怪节奏或资源表现中的一项。
3. 新增内容优先走 Luban 配置表；代码侧只保留运行时解释、发射模式和表现同步。
4. 每个实施小阶段仍需通过 `dotnet build`、`git diff --check` 和 Unity Play Mode 验收后再提交。

### 阶段 15 内容扩展计划

#### 当前内容基线

- Luban 敌人表已有 6 条数据：3 个普通敌人、2 个精英敌人、1 个 Boss。
- Luban 升级选项表已有 19 条数据，当前生存局内只接入 Reward 基础属性效果。
- Luban 被动表已有 4 条数据，但生存局内阶段 8 的 3 个被动仍由代码侧定义效果。
- 运行时武器已有 2 种：追踪魔弹和旋刃。
- 固定地图、边界、吸附拾取、HUD、结算和对象池已通过当前路线验收。
- 配置表内中文字段仍存在旧编码痕迹，用户可见文本暂由代码侧中文映射兜底。

#### 下一轮扩展优先级

1. **内容表清理与补表**：优先修复 Luban 表中文文本，补足武器表、被动效果表和刷怪阶段表，保持生成代码与 bytes 链路一致。
2. **敌人与刷怪扩展**：新增一批差异化普通敌人和精英敌人，并把刷怪权重、出现时间和精英/Boss 节点从代码阈值迁到配置。
3. **武器扩展**：新增 1 种低复杂度武器，例如近身脉冲或穿透飞镖；先复用现有投射物和舞台视图，不新增复杂进化系统。
4. **被动扩展**：把磁力、伤害、移速等被动效果迁入配置解释层，再补 1-2 个只影响现有数值的被动。
5. **资源与反馈扩展**：在玩法内容稳定后，再接入正式 Prefab、简单音效和命中特效，优先复用 TEngine 资源与音频模块。

#### 建议实施拆分

- 阶段 16：配置表清理与武器/被动/刷怪表结构补齐。
- 阶段 17：第一批敌人与刷怪节奏配置化。
- 阶段 18：第三武器最小实现与升级选项接入。
- 阶段 19：被动效果配置解释层与第一批扩展被动。
- 阶段 20：资源、音效和命中反馈最小接入。

#### 验收要求

- 每个扩展阶段必须保留现有核心闭环：开始、移动、刷怪、自动攻击、掉落、升级、结算和重开。
- Play Mode 测试应覆盖新增内容是否能被抽中、是否生效、是否与对象池和配置回退兼容。
- 不在内容扩展阶段引入技能树、稀有度、武器进化、复杂地图系统或第二套资源/配置框架。
