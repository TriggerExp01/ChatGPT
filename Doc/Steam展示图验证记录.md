# Steam 展示图验证记录

## 验证目标

本轮验证用于确认正式 UI 资产第一轮接入后，当前可演示版本是否具备 Steam 商店页视觉讨论基础，并复核上一轮修复的敌人和投射物表现尺寸是否仍然稳定。

本轮不新增玩法、不调整数值、不引入新 UI 框架，只围绕三类截图视角做方向判断：

1. 升级奖励三选一。
2. 高密度战斗。
3. 结算成长界面。

## 截图产物

- `Doc/Steam展示图验证/Steam方向_升级奖励三选一.png`
- `Doc/Steam展示图验证/Steam方向_高密度战斗.png`
- `Doc/Steam展示图验证/Steam方向_结算成长界面.png`

三张截图均使用 Unity 运行时真实画面捕获。由于 Unity MCP 的 `manage_camera` 截图不包含 Screen Space Overlay UI，本轮最终改用 `UnityEngine.ScreenCapture.CaptureScreenshot` 捕获完整 Game View，以确保 HUD、升级卡牌和结算面板入镜。

## 画面结论

### 升级奖励三选一

- HUD、奖励卡牌、图标、标题、价格和状态文案均可读。
- 第一轮 UI 图集已经能支撑“二次元轻幻想 Bullet Heaven”的奖励选择方向讨论。
- 当前仍是占位角色与占位图标，美术完成度不足以直接作为最终 Steam 商店图。

结论：适合作为 UI 方向验证图，可作为后续正式卡牌和图标资产的基准。

### 高密度战斗

- 敌人、玩家、星环脉冲、掉落物和 HUD 同屏可见。
- 普通敌人没有出现巨大化，投射物也没有出现尺寸失控，上一轮“子弹和敌人大小不一”的修复有效。
- 当前敌人排列呈规则矩阵，更像压测和技术验收画面，不像自然游戏过程中的商店展示图。
- 阶段 46 已新增固定种子的展示战斗构图入口 `DebugPopulateShowcaseRuntimeObjects`，后续自然战斗截图应优先基于该入口，而不是继续使用矩阵式压测状态。

结论：适合作为尺寸修复和对象密度验证图，不建议直接作为最终 Steam 商店页主图。

### 结算成长界面

- 胜利标题、战斗数据、本局收益、永久成长条和角色头像区域均可读。
- 结算面板整体可用于证明单局结束和局外成长闭环。
- 底部操作提示仍在结算画面下方显示，作为展示图略显杂乱；面板内可见少量底层玩家和场景透出，后续可进一步压暗背景或隐藏提示条。

结论：适合作为结算系统方向验证图，正式商店图前建议整理背景遮罩和底部提示显示策略。

## Steam 商店页适配判断

当前三张图已经能证明：

- 核心 UI 闭环完整，升级、战斗、结算三类关键界面可读。
- 正式 UI 资产第一轮已经明显优于纯运行时色块占位。
- 战斗表现尺寸修复有效，没有再出现特别大的普通敌人或异常缩放投射物。

当前三张图还不适合作为最终 Steam 商店页成稿，主要原因是：

- 高密度战斗图仍是压测构图，敌人队列过于规整。
- 角色头像、武器图标、被动图标和奖励卡面仍需正式美术。
- 结算图底部提示和背景透出需要为展示截图单独整理。

## 后续建议

1. 基于阶段 46 展示构图入口制作自然战斗构图截图，避免矩阵式排布。
2. 补齐第一批正式视觉资产：角色立绘、武器图标、被动图标、掉落物图标和奖励卡面。
3. 增加展示截图模式：允许隐藏底部操作提示、降低 HUD 透明遮挡、固定镜头和固定随机种子。
4. 保留本目录截图作为技术验收证据，不把它们直接等同于最终商店素材。

## 阶段 46 补充结论

- `DebugPopulateShowcaseRuntimeObjects(int seed = 46001)` 已提供可复现展示状态：Boss、普通/精英敌、多武器弹幕、经验/金币掉落、命中、暴击、击杀和拾取反馈同屏出现。
- 该入口只服务调试、截图和验收，不改变正常刷怪节奏和玩家流程。
- 当前仍未直接产出最终 Steam 成稿截图；下一步应在此状态基础上补截图控制，例如隐藏底部操作提示、固定 Game View 分辨率、输出到 `Doc/Steam展示图验证` 或新的正式截图目录。
