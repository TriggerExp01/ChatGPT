# 四 Agent 阶段开发工作流

本文档用于把“成品描述 -> 阶段拆分 -> 开发实现 -> Unity MCP 验收 -> 体验复盘 -> 返工/提交”的流程固定到当前 `TEngine_Game` 项目中。后续当用户给出游戏成品描述、要求自动拆阶段、要求多 Agent 接力，或要求阶段验收打回时，优先使用本文档。

## 适用场景

- 用户给出一个游戏成品描述，希望 Codex 自动拆分阶段并持续推进。
- 当前阶段需要由开发线程和验收线程分开处理。
- 阶段通过前需要 Unity MCP Play Mode 验收，失败后打回继续打磨。
- 需要把策划案、数值设计、开发总结、验收结论和体验复盘沉淀到项目文档。

## 总体流程

1. 总策划 / 制作人 Agent 读取项目文档和用户成品描述，输出“阶段开发合同”。
2. 主开发 Agent 按阶段开发合同完成当前阶段，实现代码、资源、配置、测试和文档更新，输出“阶段交付包”。
3. Unity MCP 验收 Agent 使用真实 Unity MCP 执行 Play Mode 验收，输出“验收通过”“验收不通过”或“验收阻塞”。
4. 体验复盘 / 调优 Agent 基于阶段交付包、验收结果和截图观察，输出玩家体验与下一阶段打磨建议。
5. 验收不通过时，主开发 Agent 只修复当前阶段，不进入下一阶段。
6. 验收通过后，主开发 Agent 更新开发日志和必要路线文档，执行阶段 commit。

## 角色边界

### 1. 总策划 / 制作人 Agent

- 负责产品目标提炼、阶段拆分、玩法策划、数值目标和验收标准。
- 输出“阶段开发合同”给主开发 Agent。
- 不直接改代码，不导入资源，不执行 Unity 验收。
- 必须控制阶段边界，避免一次性堆多个阶段。

### 2. 主开发 Agent

- 负责当前阶段实际开发，包括代码、资源、配置、测试和文档更新。
- 输出“阶段交付包”给 Unity MCP 验收 Agent。
- 只开发当前阶段，不处理未来阶段内容。
- 验收不通过时，只修复当前阶段问题。
- 验收通过后负责更新文档并提交 commit。

### 3. Unity MCP 验收 Agent

- 负责真实 Unity MCP Play Mode 验收。
- 不开发新功能，不修改阶段范围。
- 对当前阶段有一票否决权。
- MCP 不可用时输出“验收阻塞”，禁止进入下一阶段。
- 不允许用 batchmode、自建 Editor 验收器或桌面按键模拟替代 Unity MCP 验收。

### 4. 体验复盘 / 调优 Agent

- 负责从玩家体验、数值节奏、构筑爽感、UI 可读性、特效反馈和展示图价值角度复盘。
- 不直接改代码，不推翻 Unity MCP 验收结论。
- 将建议拆成“当前阶段是否返工”和“下一阶段建议”。
- 只给可执行建议，不输出泛泛评价。

## 硬闸门

- 每次接收项目任务后，先执行 `codegraph sync`。
- 每次只推进一个阶段。
- 当前阶段未通过 Unity MCP 验收前，不进入下一阶段。
- Unity MCP 验收必须至少满足：
  - 可读取 `editor/state`。
  - `ready_for_tools = true`。
  - `read_console`、`manage_editor`、`find_gameobjects` 或 `manage_camera` 等操作型工具至少一个可实际执行。
- `codex mcp list` 显示 enabled 不算验收通过。
- 阶段完成后至少执行：
  - `dotnet build UnityProject\UnityProject.sln --no-restore`
  - `git diff --check`
- 阶段通过验收后必须执行一次 git commit，提交信息使用中文并包含阶段编号。

## 返工提示词

```text
当前阶段被 Unity MCP 验收 Agent 打回。你继续作为主开发 Agent，只允许修复当前阶段，不允许推进下一阶段。

验收不通过报告：
【粘贴验收不通过报告】

要求：
1. 先复盘失败原因。
2. 定位相关代码、配置、资源或测试。
3. 做最小范围修复。
4. 重新执行：
   dotnet build UnityProject\UnityProject.sln --no-restore
   git diff --check
5. 重新生成阶段交付包。
6. 明确说明本次修复如何对应验收问题。
```

## 使用建议

- 最轻量用法：同一个 Codex 线程按 4 个角色顺序执行，但每一步都必须输出对应交接物。
- 推荐用法：开 4 个 Codex 线程，分别命名为“总策划”“主开发”“Unity验收”“体验复盘”，通过复制阶段开发合同、阶段交付包和验收报告交接。
- 如果当前环境后续支持自动子 Agent，可直接把本文档作为编排依据。
- 无论使用哪种方式，Unity MCP 验收 Agent 的“不通过”或“阻塞”都禁止主开发 Agent 进入下一阶段。
