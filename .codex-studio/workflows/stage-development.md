# 阶段开发工作流

## 目标

让 Codex 每次只推进当前阶段，完成后可验证、可回滚、可继续。

## 标准流程

1. 读取 `Doc/文档索引.md`。
2. 读取 `Doc/类吸血鬼幸存者阶段开发路线.md`，确认当前阶段。
3. 读取 `Doc/肉鸽系统设计总览.md`，确认玩法边界。
4. 读取 `Doc/框架使用指南.md`，确认 TEngine 框架边界。
5. 读取 `Doc/开发日志.md`，确认最近完成情况。
6. 搜索当前阶段相关代码。
7. 输出最小实现方案。
8. 修改代码。
9. 执行验证。
10. 更新开发日志。
11. 总结完成内容、改动文件、验证结果、风险点、下一步。

## 当前阶段处理原则

如果路线文档显示当前阶段是：

- 阶段 7：只做多武器与武器升级。
- 阶段 8：只做被动道具与构筑。
- 阶段 9：只做对象池与性能优化。
- 阶段 13：只做 Luban 配置化。

不得把多个未完成阶段混在同一次任务中，除非用户明确要求重排路线。

## 阶段完成定义

一个阶段只有同时满足以下条件，才算完成：

- 代码编译通过。
- `git diff --check` 通过。
- Unity Console 无新增 Error。
- Play Mode 可验证当前阶段核心行为。
- `Doc/开发日志.md` 已记录。
- 路线文档中的阶段状态已更新，或最终回复说明暂未更新原因。
