# 任务等级规则

## L1：极小修改

示例：

- 文案调整
- 注释修正
- 日志补充
- 单行 bug 修复

执行规则：

- 可直接修改。
- 修改后至少执行 `git diff --check`。

## L2：单模块小功能

示例：

- 调整 HUD 显示字段。
- 修改一个升级选项效果。
- 调整一个敌人参数。

执行规则：

- 读取相关文档和相关代码。
- 不扩大范围。
- 执行编译验证。

## L3：玩法功能

示例：

- 阶段 7 多武器。
- 阶段 8 被动道具。
- 新掉落类型。
- 新结算规则。

执行规则：

- 必须读取阶段路线、系统总览、框架指南、开发日志。
- 必须确认当前阶段。
- 必须给出最小方案。
- 必须更新开发日志。

## L4：架构/管线/重构

示例：

- Luban 配置化。
- 对象池改造。
- 热更流程调整。
- YooAsset 资源管线调整。
- UI 框架改造。

执行规则：

- 先输出方案和风险。
- 不做无边界大重构。
- 每次只改一个明确子目标。
- 必须给出回滚或验证方案。
