# 精简 Game Studio 角色

本项目不使用完整 49 Agent 模型，只保留能直接提升当前 Unity 肉鸽项目质量的 9 个角色。Codex 不需要显式模拟角色对话，但必须按这些职责审查任务。

## Producer

职责：

- 确认当前阶段。
- 控制任务范围。
- 防止跨阶段堆功能。
- 要求完成后更新开发日志和验收结果。

关键判断：

- 当前任务是否符合阶段路线？
- 是否提前做了下一阶段内容？
- 是否缺少验收？

## Game Designer

职责：

- 维护类《吸血鬼幸存者》的核心体验。
- 控制武器、被动、升级、刷怪、难度曲线的设计边界。
- 优先保证玩法闭环，不提前堆复杂系统。

关键判断：

- 新功能是否能形成明确体验差异？
- 是否容易 Play Mode 验收？
- 是否过早引入技能树、词条、稀有度、合成系统？

## Unity Architect

职责：

- 保护 TEngine 架构边界。
- 保护热更入口、模块入口、UI 框架、资源框架。
- 控制重构规模。

关键判断：

- 是否应该走 `GameModule`？
- 是否把业务堆进 `GameApp`？
- 是否绕开了 TEngine 已有能力？
- 是否误改 `Assets/TEngine`？

## Gameplay Programmer

职责：

- 实现玩家、敌人、武器、掉落、升级、难度曲线、结算等核心逻辑。
- 优先以最小改动完成当前阶段。
- 保持代码清晰，避免过度抽象。

## UI Programmer

职责：

- 实现 HUD、升级三选一、结算界面和操作提示。
- UI 只负责显示、输入转发和状态反馈，不直接持有核心战斗规则。
- 打开窗口优先走 `GameModule.UI.ShowUIAsync<T>()`。

## Resource Pipeline Engineer

职责：

- 处理 Prefab、美术资源、音频资源、YooAsset 资源加载规则。
- 阶段未到时不提前大规模资源管线改造。
- 不主动引入 Addressables。

## Config Engineer

职责：

- 负责 Luban 配置迁移。
- 敌人、武器、升级选项、被动、刷怪规则按阶段逐步配置化。
- 阶段 13 前不强行全量配置化。

## QA Tester

职责：

- 维护 Play Mode 验收标准。
- 检查 Unity Console 0 Error。
- 检查当前阶段核心行为是否可视化通过。

## Performance Analyst

职责：

- 关注 GC、实例数量、投射物、敌人、掉落物、UI 刷新频率。
- 阶段 9 前只提出风险，不提前大规模对象池改造。
- 优化必须基于实际问题或阶段要求。
